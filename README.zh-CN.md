# Agent Memory

**维护 AI 每次会话都会读的那个记忆文件。**

这是一个 Obsidian 插件，给「把长期记忆放在 Markdown 里、让 AI 自己读」的人用。
它做三件事：生成主题索引、盯住字符预算、检查记忆有没有烂掉。

[English](README.md) · MIT · Obsidian ≥ 1.4.0 · 仅桌面端

---

## 要解决的问题

你把记忆放在 Obsidian，AI 每次开场读一个文件。一开始挺好用——直到那个文件涨到 6000 字符，
**其中一半的内容其实从来没送到过它眼前，而且没有任何人告诉你**。

有三个问题：

1. **注入层超出平台上限。** 超出的部分被直接丢掉，不报错、不提示。AI 回答得跟那段内容从没存在过一样。
2. **主题索引漂移。** 你新建了 `AI记忆/主题/docker.md`，忘了往注入层的索引表加一行，
   这个主题从此对 AI 隐形。
3. **没人审计记忆。** 过期主题、被引用却已删除的文件、没有触发词的主题——全都看不见，
   直到某天出事。

这个插件在 Obsidian 里处理这三件事。

## 为什么「让 AI 自己先读一遍」一定会失败

我们试过。往启动文件里写了这么一条：

> 每次会话的第一件事，先读这 4 个文件：索引、状态、协作说明、事实表。

**一周后：零次执行。一次都没有。**

原因是成本核算，而且这个核算是对的。读 4 个文件 = 4 次工具调用 + 约 30 KB 上下文。
而自动注入的那个文件里，红线、机器事实、偏好全都已经有了——只差一行「当前状态」。
读的边际收益很小，成本却看得见。所以模型跳过它，每一次都跳。

**一条永远不被执行的规则，比没有规则更糟。** 它会告诉模型：这个项目里的规则是可以商量的，
你下一条规则会继承这个印象。

这个结论决定了整套设计：

> 别让 AI 去取记忆，把记忆放到它躲不开的地方。

## 有一个预算，但没人告诉你边界在哪

注入的上下文不是无限的。超过某个点，尾部被静默丢弃——不报错、不提示，
AI 回答得跟那段内容从不存在一样。

**我们不提供具体数字，因为不存在通用值：**

- 真实上限按 **token** 算，不是字符。字符数只是个代理指标，中英比例一变，这个换算就偏。
- 它随平台、版本、模型上下文窗口变化。

**所以插件给的是探针，不是数字。**

1. 跑命令 **写入测量探针** —— 往注入层末尾追加一行唯一的 `PROBE-XXXX`。
2. 开一个新会话，问你的 AI：**「你读的那个文件，最后一行写的是什么？」**
3. 它把探针复述出来了 → 这一行没被截断；没复述 → 截断点在它上面，减一点再试。
4. 跑 **移除测量探针**，把测出来的字符数填进设置。

之后状态栏显示 `已用 / 你设的线`，超 90% 变橙、超 100% 变红。
**没设线的时候只显示当前字数**——编一个默认值，等于告诉你一件我们并不知道的事。

## 三层结构，只有一层是保证的

| 层 | 在哪 | 什么时候加载 | 可靠吗 |
| --- | --- | --- | --- |
| **L0** | 注入层文件（`MEMORY.md`、`AGENTS.md`…） | 每次会话，平台强制注入 |
| **L1** | `AI记忆/主题/*.md` | 命中触发词才读 | 大致可靠——取决于查表够不够便宜 |
| **L2** | 项目笔记、对话归档 | 问到具体的事才翻 | 不可靠——需要真的去挖 |

只有 L0 是保证的，因为注入不需要模型同意。其他层必须**便宜到真的会被执行**——
这就是为什么 L1 的每条要写 `trigger`，也是为什么索引表必须短。

## 这个插件做什么

### 1. 生成主题索引

扫一个目录，读每个主题文件 frontmatter 里的 `trigger`，把对照表写进注入层文件——
**只写两个标记之间，其他内容一个字都不动**。

```yaml
---
trigger: docker / compose / container / 容器
summary: 这台机器上 Docker 是怎么配的
---
```

生成：

| 提到这些词 | 读这个 |
| --- | --- |
| docker / compose / container / 容器 | `AI记忆/主题/docker.md` |

新建主题文件 → 跑一次「重建主题索引」，完事。不用再改两个地方。

### 2. 盯住字符预算

状态栏显示 `已用 / 上限`，点一下复制注入层文件的绝对路径。

### 3. 审计记忆

「检查记忆健康度」会报：

- 注入层超预算（或快超了）
- 没有 `trigger` 的主题笔记（它们永远进不了索引）
- N 天没更新的主题
- 注入层里引用了但已经不存在的路径

## 它不做什么

说清楚，免得你期待错方向：

- **它没法让 AI 去读记忆。** 那只有平台的注入能做到。如果你的 AI 没有一个「每次会话自动读的文件」，
  这个插件没有可管理的东西。
- **它不做对话归档。** 那件事得在 agent 或系统层做，不在 Obsidian 里。想要的话配个独立脚本。
- **它不同步多设备。** 用 Obsidian Sync、git，或者你本来就在用的东西。
- **它只往一个 vault 外的文件写东西**——你配置的那个注入层文件，别的不碰。

## 安装

### 从源码装（暂时）

```bash
git clone https://github.com/kldcg/obsidian-agent-memory
cd obsidian-agent-memory
npm install
npm run build
```

把 `manifest.json`、`main.js`、`styles.css` 复制到 `<你的库>/.obsidian/plugins/agent-memory/`，
然后在 设置 → 第三方插件 里启用 **Agent Memory**。

## 配置

1. **设置 → Agent Memory → 注入层文件**
   点「自动检测」扫常见位置，或者自己填绝对路径。常见的值：
   - WorkBuddy —— `~/.workbuddy/user-<uuid>-personal/MEMORY.md`
   - Claude Code —— `~/.claude/CLAUDE.md`，或项目里的 `AGENTS.md`
   - Cursor —— `~/.cursorrules`，或项目里的 `AGENTS.md`
2. **注入层预警线** —— 填你自己测出来的字符数，或填 `0` 只显示字数、不做判断。
   测法见上面「探针」那一节。
3. **主题目录** —— 主题笔记放哪，例如 `AI记忆/主题`。
4. 在注入层文件里放一对标记：

```markdown
<!-- agent-memory:index:begin -->
<!-- agent-memory:index:end -->
```

没有标记时，索引会被追加到文件末尾，并提示你把它挪到合适的位置。**其他内容不会被改动。**

## 一个最小可用的目录骨架

```
你的库/
├── AI记忆/
│   ├── 主题/
│   │   ├── docker.md          # trigger: docker / container / 容器
│   │   └── printer.md         # trigger: 打印 / 打印机
│   └── 会话状态.md             # 详细经过，按需才读
└── 项目/
    └── 2026-11-17 迁移.md
```

注入层文件（`MEMORY.md`），控制在上限以内：

```markdown
## 当前状态
- 在推：…

<!-- agent-memory:index:begin -->
| 提到这些词 | 读这个 |
| --- | --- |
| docker / container / 容器 | `AI记忆/主题/docker.md` |
<!-- agent-memory:index:end -->

## 规则
- …
```

## 隐私

- **读**：你配置的注入层文件路径，以及库内的 Markdown 文件。
- **写**：注入层文件（只改索引块）和本插件自己的设置文件。
- **网络**：完全没有。无遥测、无更新检查、无远程请求。
- 只有健康检查需要验证注入层里引用的路径时才去读别的文件。

`isDesktopOnly: true` —— 读库外文件要用 Node 的 `fs`，移动端拿不到。
